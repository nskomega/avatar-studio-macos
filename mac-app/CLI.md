# Аватар Студия: одна команда по SSH

Версия 0.5.0. Команды выполняются **на Mac с проектом, моделями, базой и установленными
окружениями**, под тем же пользователем, у которого настроен rclone. GUI открывать не нужно.
Копирования одной .app на другой компьютер недостаточно: путь проекта находится в Info.plist.
После переноса проекта выполните mac-app/build.sh на новом Mac с подготовленными зависимостями.

## Разовая настройка Google Drive

На Mac, где будут генерироваться ролики:

```sh
brew install rclone
rclone config
```

В мастере создайте новое подключение с именем `gdrive`, типом **Google Drive**.
Завершите вход в нужный Google-аккаунт и предоставление запрошенного доступа.
Опции client_id/client_secret можно оставить пустыми для стандартного клиента rclone.
Для обычного My Drive не выбирайте Shared Drive. Токен остаётся в конфигурации rclone,
его не нужно вставлять в приложение, SQLite, Git или команду генерации.

**Если подключены только по SSH:** на вопрос об автоматическом открытии браузера ответьте
`n`. Выполните показанную мастером команду `rclone authorize "drive" …` на вашем компьютере
с браузером и rclone той же версии; перенесите результат обратно в мастер на серверном Mac.
Следуйте именно напечатанной команде — дополнительные параметры зависят от выбранной конфигурации.

Проверьте вход и сохраните назначение студии:

```sh
rclone lsd gdrive:
"./mac-app/studio" drive-setup --destination 'gdrive:AvatarStudio'
```

`drive-setup` проверяет наличие бинарника и имени remote, но не заменяет проверку
авторизации `rclone lsd`. Папку AvatarStudio создаёт сама загрузка.
Настройки назначения: mac-app/data/integrations.json, без OAuth-токена.
В приложении тот же адрес настраивается через Файл → Настроить Google Drive.

Инструкция проверена по официальным документам:
[установка](https://rclone.org/install/#macos-installation),
[Google Drive](https://rclone.org/drive/),
[авторизация без браузера на сервере](https://rclone.org/remote_setup/).

## Одна команда: аватар + полный сценарий + заголовок + Drive

Полный исходный SMS-сценарий сохранён в mac-app/tests/fixtures/structured-scenario.txt.
Команда ниже — один запуск, переносы `\` добавлены для удобства чтения:

```sh
"./mac-app/studio" generate \
  --avatar "./local-avatar" \
  --scenario-file "./mac-app/tests/fixtures/structured-scenario.txt" \
  --title "SMS 2FA — не идеальная защита" \
  --logo "./assets/branding/logo.png" \
  --upload 'gdrive:AvatarStudio' --detach
```

`--logo` необязателен. `--upload` без значения использует заранее сохранённое назначение
(по умолчанию gdrive:AvatarStudio). Без `--upload` ничего не отправляется в облако.
Можно запускать и непосредственно бинарник программы:
`mac-app/build/Аватар Студия.app/Contents/MacOS/AvatarStudio` с теми же аргументами.

**Сценарий прямо внутри одной команды**, без файла:

```sh
"./mac-app/studio" generate --avatar "./local-avatar" --scenario 'СЦЕНА 1 — ХУК. Озвучка: «Проверь поддержку passkeys в важных аккаунтах». Текст: «ПРОВЕРЬ ЗАЩИТУ».
СЦЕНА 2 — ВЫВОД. Озвучка: «Перешли коллеге, которому это пригодится». Надпись: «СОХРАНИ И ПЕРЕШЛИ».' --title 'Проверка защиты' --upload 'gdrive:AvatarStudio' --detach
```

Для сложного текста с кавычками удобнее stdin без подстановок shell:

```sh
"./mac-app/studio" generate --avatar "./local-avatar" --scenario-stdin --title 'Мой ролик' --upload --detach <<'SCENARIO'
СЦЕНА 1 — ХУК. Озвучка: «Первая реплика». Текст: «ЗАГОЛОВОК».
СЦЕНА 2 — ВЫВОД. Озвучка: «Вторая реплика». Надпись: «ВЫВОД».
SCENARIO
```

Экранированный разделитель `'SCENARIO'` сохраняет текст буквально: команды, `$` и обратные
кавычки в сценарии не исполняются оболочкой.

## Проверить план без запуска моделей

```sh
"./mac-app/studio" prepare --scenario-file "./mac-app/tests/fixtures/structured-scenario.txt" --title 'SMS 2FA'
```

`generate` автоматически подготавливает этот же план и сохраняет prepared-plan.json.
Для неинтерактивного запуска CLI отдельного диалога подтверждения нет: команда generate
означает запуск с получившимся планом. Для проверки используйте сначала prepare.
Распознаётся русский структурированный формат `СЦЕНА N … Озвучка: «…»` и экранные
`Текст: «…»`, `Надпись: «…»`; также кавычки “…” и "…". Это локальный разбор шаблона,
а не LLM, выполняющая произвольные указания. Указания не становятся кодом или командами.
Неподдерживаемые/неоднозначные входы отклоняются, оригинал всегда сохраняется.

## Фоновая работа, статус, остановка, повтор загрузки

`--detach` возвращает JSON с папкой задания, PID, путями run.log и status.json.
Worker создаёт отдельную сессию с закрытым stdin и журналом в файле, поэтому
обычное отключение SSH его не останавливает. Сам Mac должен оставаться включённым;
caffeinate предотвращает сон по бездействию, но не ручной сон/закрытие крышки.
Без --detach команда ждёт завершения; Ctrl+C/TERM передаёт движку запрос остановки.

Для конкретной папки из ответа команды:

```sh
"./mac-app/studio" status "./mac-app/jobs/ID_ИЗ_ОТВЕТА"
tail -f "./mac-app/jobs/ID_ИЗ_ОТВЕТА/run.log"
```

Для остановки фонового задания отправьте `kill -TERM PID_ИЗ_ОТВЕТА`, предварительно
проверив, что это ещё тот же worker. Не используйте SIGSTOP для Metal.
Если загрузка упала, результат остаётся в videos/exports, а статус — upload_error:

```sh
"./mac-app/studio" retry-upload "./mac-app/jobs/ID_ИЗ_ОТВЕТА" --destination 'gdrive:AvatarStudio'
```

Повторная загрузка не вызывает модели. Коды завершения generate: 0 — завершено
(для detach — worker запущен), 1 — ошибка генерации, 2 — параметры/предварительные
проверки, 3 — ошибка загрузки, 130 — остановка. При detach итог смотрите в status.json.
Технический сбой авторизации в повторной загрузке возвращает ненулевой код;
исходный статус сохраняется до успешной отправки.

## Что именно создаётся и отправляется

Сначала синтезируются реплики, затем общий timing.py собирает аудио с естественными
короткими паузами. Паузы от 0.85 с останавливают задачу до генерации лица.
Сценические таймкоды из задания не заполняются тишиной и не ускоряют голос.
Речь может оказаться короче/длиннее запрошенных 35–40 с: это отражается в отчёте.

Герой генерируется по новой речи короткими планами; между ними идут иллюстративные
анимированные карточки, сравнения, схемы и чек-листы по тексту сценария.
Факты и реальные скриншоты не выдумываются. Музыка без выбранного файла не добавляется.
Субтитры сгруппированы по несколько слов, времена внутри реплик приблизительные.
Для героя используется отдельная область изображения и нижняя полоса субтитров:
это сохраняет весь кадр с лицом, столом и предметами без тесного кадрирования.

Локальная сдача: videos/exports/<название-ID>/ — MP4 (или WAV с --voice-only),
SRT для видео, report.json и scenario.json. Страница проекта — projects/<название-ID>/README.md.
В Drive копируется **только эта папка** в AvatarStudio/<название-ID>/.
Референс голоса, портрет, сырые клипы, модели, SQLite и журналы не отправляются.
Используется rclone copy --immutable с повторами, без sync/удаления чужих файлов.

После полного декода проверяются геометрия, длительность и звук. Отчёт честно
сохраняет human_review=pending: автоматический запуск и загрузка не подтверждают
сходство голоса, удачное лицо и артикуляцию. Загруженное видео требует просмотра
перед публикацией; публикации в соцсети этот CLI не выполняет.

## Очередь 0.5.0

Импорт и случайная папка доступны в GUI. Для автоматизации:

```sh
python3 mac-app/engine/batch.py inspect mac-app/examples/scenarios.json
local-avatar/.venv-lipsync/bin/python mac-app/engine/batch.py run mac-app/jobs/batch-ID
```

Вторая команда продолжает уже созданную GUI-очередь, пропуская выполненное.
Один worker за раз; ошибка ставит очередь на паузу. Подробности создания из GUI — README.
