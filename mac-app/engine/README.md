# Движок Аватар Студии 0.6.0

## scenario.py

Локальный детерминированный parser русского структурированного сценария. stdin JSON
source/title → stdout JSON source/speech/utterances/scenes/warnings. Поддерживает
Озвучка и экранные надписи в «…», “…” и "…", нумерованные СЦЕНА N с одной/несколькими
репликами. Нет shell/eval/LLM и автоматического фактчекинга. Исходник сохраняется.
validate_plan перепроверяет соответствие source, scenes, utterances и speech.
actual_timeline связывает сцены с фактическими аудиоинтервалами, а не таймкодами задания.

## pipeline.py и voice.py

Pipeline принимает project.json только из mac-app/jobs/<ID>. Конфигурация:
photo/reference_audio/reference_text/script, необязательные logo/voice_only/design,
scenario_plan/source_prompt/title/upload_destination. Для старого задания без плана
план строится автоматически. Голос синтезирует voice.py в .venv-tts-compare, ESpeech RL-V2,
seed=42, nfe_step=32, speed=1.0, словарные ударения и TTS-написания. Референсы сохраняются снимками в jobs.
Чтение названий задаётся spoken_terms в voice-settings.json: «Битрикс24» →
«Би́трикс два́дцать четы́ре» только для TTS. Сценарий и субтитры сохраняют оригинал;
pronunciation-plan.json содержит canonical_text и фактический marked.

Speech-first timing использует общий local-avatar/reels/timing.py. По краям реплик
обрезается тишина с запасом 80 мс. Тихие интервалы >=0.85 с сокращаются до 0.35 с
без ускорения речи; исходные voice-NNN.wav сохраняются. Правки по репликам записываются
в timing-check.json (координаты после обрезки краёв). Повторный аудит всего аудио
по-прежнему останавливает задачу до LTX, если остались паузы >=0.85 с.
Предел речи — 90 с; длительность из брифа только ориентир, без немых добивок.
Первый/последний планы и явно упомянутый герой — LTX с новой речью по 3 с максимум.
Каждый дубль проверяется hero_check.py через MediaPipe: наличие лица и изменение
отношения зазора губ к ширине рта. Проверяется только используемый интервал клипа.
При браке — ещё один seed, затем остановка до монтажа. Дубли и hero-check-NNN.json
сохраняются. Это эвристика неподвижного рта, не оценка точной синхронизации;
порог открытия 0.025, изменения p90−p10 0.015, покрытия лица 80% требуют дальнейшей
калибровки. Проверка артикуляции и сходства человеком остаётся обязательной.
Последняя сцена с чек-листом после первого плана переходит к графике.
Графические сцены не вызывают модель и развивают карточки/схемы по исходной речи.

## storyboard.py

720×1280, 24fps, H264/AAC, две CPU-нити кодировщика. Весь кадр героя помещается
в viewport y=100..900 без увеличения лица и кадрирования. Субтитры — отдельный
блок от y=930 (графика y=948), нижний край не ниже y=1060. Это исключает перекрытие лица/стола подложкой.
Надписи/логотип — над viewport. Короткие субтитры получают пропорциональные времена
внутри реплики; это не ASR-выравнивание. SRT и диагностический storyboard сохраняются.
Сравнения, схемы и чек-листы — иллюстрации предоставленного текста, не результаты опытов.

После полного декода проверяются размер, звук и длительность. Пакет сдачи содержит
MP4/WAV, SRT, report.json и scenario.json в videos/exports/<название-ID>.
README проекта создаётся в projects/<название-ID>/. human_review=pending остаётся
в отчёте: технические проверки не доказывают сходство/мимику/удачный монтаж.
Старая функция export сохранена для воспроизведения и исторического smoke-check.py.

## studio_cli.py / mac-app/studio

GUI executable при наличии аргументов заменяет себя через execv на Python CLI.
Команды: prepare, generate, drive-setup, status, retry-upload, внутренний run-job.
Сценарий — --scenario / --scenario-file / --scenario-stdin. --detach отделяет worker
от SSH; логи/статус/PID сохраняются в jobs. Foreground передаёт TERM/INT worker-у.
Описание кодов завершения и рабочие примеры: ../CLI.md.

## drive_upload.py

Rclone с уже пройденным OAuth, по умолчанию gdrive:AvatarStudio. Токены не читаются
и не копируются студией. Предварительно проверяются бинарник и наличие имени remote,
не реальная валидность OAuth (проверка пользователем rclone lsd).
copy --immutable с повторами отправляет только папку сдачи. Ошибка даёт upload_error
с локальным output; retry-upload не запускает модели. Реальная отправка требует
установки rclone и авторизации пользователя.

## Проверки без моделей

```sh
python3 mac-app/tests/test_scenario.py
python3 mac-app/tests/test_history.py
zsh mac-app/tests/profile-smoke.sh
local-avatar/.venv-lipsync/bin/python mac-app/tests/test_pipeline_flow.py
local-avatar/.venv-lipsync/bin/python mac-app/tests/check_storyboard.py
```

Pipeline-flow использует явно замоканные ML workers и временную тестовую базу путей,
не проверяет голос/лицо модели. Storyboard smoke использует старый клип и независимую
аудиозапись только как layout fixtures; они не выдаются за новый lip-sync результат.

## history.py — локальная библиотека

SQLite `mac-app/data/studio.sqlite3`, schema user_version=1; стандартный sqlite3 Python.
Таблица prompts: исходный промпт, произносимый текст, заголовок, дата, ID по содержимому.
Таблица generations: уникальная папка задания, дата, полный project.json, текущий
сохранённый статус, сообщение и путь результата. Медиа остаются в jobs.
Параметризованные SQL-запросы, WAL, timeout=10 с, транзакции с закрытием соединения.

- `python3 mac-app/engine/history.py sync`: импорт jobs и script-source-*.txt.
- `python3 mac-app/engine/history.py list --query 'текст'`: JSON для UI.
- `python3 mac-app/engine/history.py save`: JSON source/speech/title через stdin.
- `python3 mac-app/engine/history.py record --job /absolute/job`: индекс одного задания.
- `python3 mac-app/tests/test_history.py`: изолированные временные SQLite-базы.

Импорт повторяемый; тестовые smoke/lock-check/ui-preview пропускаются. Повреждённые
JSON не останавливают импорт остальных, предупреждения возвращаются UI.
Запись регистрируется перед запуском, pipeline.status обновляет базу на каждом этапе.
Ошибка базы в pipeline журналируется и не прерывает генерацию. Следующее открытие
истории восстанавливает индекс из project.json/status.json. Отсутствующий статус
обозначается unknown; незавершённый этап — последний записанный, не подтверждение
живого процесса. Результат открывается только при фактическом наличии файла.

База и её WAL/SHM исключены из Git. Для резервной копии используйте SQLite backup API
либо копируйте data вместе с jobs после завершения процессов приложения/движка.
Один SQLite-файл не содержит сами медиа. Перенос проекта требует обновления абсолютных
путей исторических заданий. Старые экспортные каталоги вне jobs автоматически не импортируются.

## batch.py / doctor.py (0.5.0)

batch.inspect проверяет JSON/CSV/TXT; create_queue валидирует весь пакет, выбирает
и сохраняет фото каждого задания. run_queue исполняет задания последовательно,
останавливается на ошибке и пропускает done при продолжении. Отдельный flock
защищает очередь. SIGTERM передаётся текущему pipeline, который завершает детей.

doctor проверяет импорты трёх окружений, пути моделей, словарь и бинарные утилиты
без загрузки моделей. Это проверка готовности, а не качества синтеза или lip-sync.
